Hexo 主题架构与从零发布指南

2026-10-10 · 预计阅读时长 6 分钟 · 适用层级：进阶

在传统静态博客开发中，设计与实现往往容易出现断层：要么追求炫目复杂的 JavaScript 框架引入沉重负担，要么排版简陋缺乏个性。松烟主题的核心哲学是「外古内今，分卷而治」——词卷重仪式与古风韵味，技术文则必须回归纯粹的现代阅读与工程效率。

一、分卷架构：scripts/type-mapping.js

Hexo 原生没有「分卷」或「多形态文章类型」的直接概念。通常需要借助 Front-matter 中的 type 字段，或通过主题 Filter 插件实现按目录层级映射（如 ci/** -> ci, tech/** -> tech）。

以下是主题中的类型映射插件完整实现：

javascript 
hexo.extend.filter.register('before_post_render', function (data) {
  const map = hexo.theme.config.type_mapping || {};
  const src = (data.source || '').replace(/\\/g, '/');

  // 只在用户未显式声明时用路径兜底
  if (!data.type) {
    for (const [pattern, type] of Object.entries(map)) {
      const prefix = pattern.replace(/\*\*.*$/, '').replace(/\*.*$/, '');
      if (prefix && src.startsWith(prefix)) {
        data.type = type;
        break;
      }
    }
  }

  // 白名单兜底，任何情况都不让 type 失控
  const valid = ['ci', 'essay', 'tech', 'project'];
  if (!valid.includes(data.type)) data.type = 'tech';

  return data;
});

二、CSS 自定义属性与无框架原则

主题严禁使用任何外部 CDN 样式或重型 CSS 框架，所有设计令牌集中于 tokens.css。在技术文中，代码块使用深色独立上下文（--code-bg: #1E1E1E），而不向全站宣纸背景扩散。

css 
:root {
  color-scheme: light;
  --paper:        #F7F2E7;
  --ink:          #1F1F1F;
  --cinnabar:     #B23A2F;
  --bamboo:       #6B7F5E;
  --ochre:        #B08D57;
  --ease-ink:     cubic-bezier(0.22, 1, 0.36, 1);
  --dur-enter:    320ms;
  --dur-feedback: 160ms;
}

三、技术文右栏札记的折角纸笺

技术文右侧摒弃了冗余的目录浮窗（v0.1 不实现 TOC，静默忽略），取而代之的是纯 CSS 三角实现的「折角纸笺」札记栏。悬停时切角平滑展开 2px（transition: 200ms），在极度克制的前提下提供现代纸质触感。
